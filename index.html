01 · OVERVIEW

Project Overview

The goal of this Google Summer of Code project is to develop a modular Ethernet and switched Ethernet model for the ns-3 network simulator. The implementation is designed to model modern full-duplex Ethernet networks and provide the basic building blocks required to construct Ethernet links and multi-port Ethernet switches.

The Ethernet implementation is organized into separate components for the channel, NetDevice, MAC and PHY layers. This separation allows the individual parts of the Ethernet stack to be developed, tested and extended independently while keeping their interactions close to the behavior of real Ethernet devices.

Ethernet Foundation

The EthernetChannel models the physical link connecting Ethernet devices. It provides configurable properties such as data rate, cable length and propagation speed. The propagation delay is calculated from the physical length of the channel and the configured propagation speed. The channel is responsible for propagating transmissions between connected devices.

The EthernetNetDevice provides the ns-3 NetDevice interface and acts as the interface between the ns-3 networking stack and the Ethernet implementation. It manages packet transmission and reception together with the required transmission and reception queues.

The EthernetMac handles Ethernet frame processing and MAC-level transmission and reception. The implementation models transmission states and the Ethernet inter-frame gap. It also processes Ethernet control frames used for flow control.

The EthernetPhy represents the physical layer and coordinates transmission between the MAC and EthernetChannel. Transmission timing is derived from the configured Ethernet link data rate, while the channel provides the propagation behavior.

Switched Ethernet

On top of the Ethernet foundation, the project introduces a modular Ethernet switch. The switch consists of a Switch object and multiple SwitchPort instances. Each switch port acts as an Ethernet NetDevice connected to an Ethernet link, allowing multiple hosts to communicate through the switch.

When a frame arrives at a switch port, it is passed to the switch for processing. The switch examines the Ethernet source and destination MAC addresses. Source MAC addresses are learned and associated with the port through which they were received. This allows subsequent frames destined for a known address to be forwarded through the appropriate switch port.

If the destination MAC address is not present in the forwarding table, the switch floods the frame to the appropriate ports. As traffic flows through the network, the switch gradually builds its MAC forwarding table.

Packet Scheduling

The switch uses a scheduler abstraction to separate packet scheduling from the core switching logic. This makes the scheduling mechanism extensible and allows different scheduling policies to be implemented without changing the basic forwarding functionality.

A First-Come, First-Served (FCFS) scheduler has been implemented as an initial scheduling policy. The scheduler tracks transmission state and determines when queued packets can be transmitted through the switch ports. The design provides a foundation for adding additional scheduling algorithms.

Ethernet Flow Control

Full-duplex Ethernet flow control is modeled using IEEE 802.3 PAUSE frames. When the receiving side experiences queue pressure, a PAUSE control frame can be generated to request that the transmitting side temporarily stop normal data transmission.

The implementation models the interaction between receive queues, PAUSE frame generation and transmission pause/resume behavior, providing a foundation for studying congestion and flow-control behavior in switched Ethernet networks.

In Summary

The project progresses from a basic Ethernet link consisting of an EthernetChannel, EthernetNetDevice, EthernetMac and EthernetPhy to a multi-port switched Ethernet architecture consisting of Switch, SwitchPort, MAC learning and packet scheduling. The resulting design provides a reusable and extensible foundation for Ethernet network simulations in ns-3.

02 · TIMELINE

Project Timeline

Community Bonding

Understanding the Architecture

Studied the existing ns-3 networking architecture and discussed the requirements, design decisions and implementation approach for the Ethernet module.

Phase 1

Ethernet Foundation

Developed the EthernetChannel, EthernetNetDevice, EthernetMac and EthernetPhy components and established full-duplex Ethernet communication.

Phase 2

Ethernet Switch

Implemented the Switch and SwitchPort architecture and connected multiple Ethernet links through a switch.

Phase 3

MAC Learning & Scheduling

Added MAC address learning, forwarding behavior and the scheduler abstraction with an initial FCFS implementation.

Final Phase

Testing & Validation

Added and executed tests and examples to validate Ethernet links, timing, switching, packet forwarding and end-to-end connectivity.
